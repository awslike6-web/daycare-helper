# 원시 메모 노션 자동 저장·기기 공유 계획

## 사용자 흐름과 저장 기준

교사가 입력할 때 기존 AES-GCM 기기 임시보관을 유지하고, 마지막 입력 뒤 5초 또는 연속 입력 30초마다 Worker를 통해 노션에 저장합니다. 화면 숨김·이동 때는 keepalive 전송을 추가로 시도합니다. 종료 순간 전송을 보장하지 않으며 미전송 내용은 다음 로그인에서 복원·재전송합니다. PC는 같은 교사·원아·날짜의 메모를 최초 진입·대상 변경·화면 복귀·활성 상태 30초마다 조회합니다.

## 구현 경계

1. 기존 일지 DB의 실제 원시 메모·교사·학급·원아·날짜 속성을 재사용합니다. 자동 메모는 별도 식별 제목과 메타데이터로 구분하고 검수 완성본을 변경하지 않습니다. 사진과 AI 생성물은 이번 자동 전송 대상에 포함하지 않습니다.
2. GET/PUT /api/memo는 서버 세션과 실제 담당반·원아를 검사합니다. 교사·날짜·원아별 MemoStore Durable Object로 쓰기를 직렬화하고 노션 확인 후에만 저장 완료로 응답합니다. 예상 버전 비교로 동시 편집을 거부하고 응답이 불명확한 최초 생성은 조회로 확인하여 중복 생성하지 않습니다.
3. public/js/memo-sync.js는 입력 대기·전송·동기화·오프라인 복원·충돌 선택을 담당합니다. 새 모듈을 기존 기기 초안·음성 입력·인증·원아/날짜 전환 파사드에 연결합니다. 대상 변경 뒤 늦은 응답을 격리하고 미전송 초안은 대상별 암호화 보관합니다.
4. 메모 아래에 노션 저장 상태·시간·지금 저장/조회와 두 기기의 충돌 해결을 표시합니다. 화면 비우기는 해당 기기 편집창만 비우고 저장된 노션 메모를 삭제하지 않습니다. 삭제와 빈 메모의 자동 덮어쓰기를 허용하지 않습니다.
5. 노션 속성 도감·명세·부품 지도·문서 및 앱 가이드·작업 보고서를 함께 갱신합니다. 프로젝트 헌법의 자동/종단 검증에 따라 가상 자료로 입력→노션→두 번째 기기→충돌·오프라인 재진입을 확인하고 모바일/PC 레이아웃을 기록합니다. 운영 연구반 가상 기록으로 실제 노션 쓰기·읽기를 확인 후 보관합니다.
6. 전사 AI 검사 후 Worker 배포·한국어 커밋/푸시·노션 4계층 개발 기록을 완료합니다. 금융·다른 앱·실제 교사의 PIN과 기존 일지는 수정하지 않습니다.

## 완료 기준

- AI 생성 없이 입력한 원시 메모가 노션에 저장되고 같은 교사의 다른 등록 기기에서 조회됩니다.
- 동일 내용 반복·노션 쓰기 응답 유실·동시 편집이 중복 생성이나 조용한 덮어쓰기로 처리되지 않습니다.
- 미전송/충돌 내용이 대상별 암호화 초안으로 남고 네트워크 복구 시 다시 확인합니다.
- 자동 메모 저장과 완성 서식의 검수 저장 상태를 별도로 안내합니다.
