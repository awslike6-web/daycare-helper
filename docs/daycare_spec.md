# 보육비서 명세서 (SSOT)

버전: 3.6.3 · 개정: 2026-10-04 · 운영 배포·공개 파일 일치 확인 완료

공식 앱: https://daycare-helper.awslike6.workers.dev/
공식 저장소: https://github.com/awslike6-web/daycare-helper

## 목적과 실제 흐름

사랑반과 소망반 교사가 거친 관찰 메모를 남기고, 실제 누적 기록으로 서류를 작성·검수·복사하여 서류 작성 시간을 줄입니다. 한그루와 키즈노트에는 교사가 직접 붙여넣으며 자동 발송하지 않습니다.

1. 일회용 등록 링크로 자기 휴대폰과 개인 PIN을 등록합니다.
2. 로그인한 교사의 노션 담당반에서 원아·작성일을 선택하고 메모·사진을 입력합니다. 원시 메모는 AI 생성 없이 자동 노션 저장하고 다른 등록 기기에서 조회합니다.
3. 관찰·평가·상담 준비에 쓸 과거 기록을 기간별로 조회하고 직접 선택합니다.
4. 필요한 7종 서식만 생성합니다. 서버는 원시 메모와 실제 선택 기록의 관찰 요약·원시 메모·관찰문을 전달합니다.
5. 원아 ID·오늘 원문 발췌·관찰 요약을 확인하여 개인 기록으로 연결합니다. AI 생성 전 원시 메모 단계에서도 같은 연결을 지원합니다. 문장·놀이 관찰·배움·성찰·지원은 검수 후 저장합니다.
6. 저장본을 재조회·복원하여 한그루·키즈노트에 복사하거나 현재 서식을 인쇄합니다.

## 실행과 인증

- Modern Vanilla JS/CSS 화면과 API를 같은 Cloudflare Worker에서 제공합니다.
- Durable Object AuthStore가 PIN 해시·일회용 초대·기기·세션·실패 횟수·교사별 초안 키를 보관합니다.
- PIN은 서버 비밀값·개별 salt와 PBKDF2 SHA-256으로 저장합니다. 브라우저에는 HttpOnly·SameSite=Strict 쿠키를 전달하며 HTTPS에서 Secure입니다.
- 기기 등록은 최초 등록 또는 마지막 성공한 PIN 로그인부터 30일입니다. 유효한 등록 기기의 PIN 로그인이 성공하면 서버 만료 시각과 HttpOnly 기기 쿠키를 함께 30일 연장합니다. 이미 등록한 기기도 배포 후 다음 PIN 로그인부터 적용됩니다.
- 같은 교사는 여러 기기·브라우저를 각각 일회용 링크와 기존 PIN으로 등록할 수 있습니다. 등록 토큰·만료·해제는 브라우저별로 독립적이며, 새 기기 등록으로 기존 기기를 해제하지 않습니다. 원시 메모는 같은 교사·원아·날짜로 공유 조회하며 미전송 초안·사진·검수 중 서식은 기기 전용입니다.
- ‘로그인 상태를 최대 30일 유지하기’는 세션 수명만 선택합니다(선택 시 최대 30일, 미선택 시 1일). 기기 등록은 두 경우 모두 성공한 PIN 로그인마다 30일 연장합니다. 서버 세션의 1시간 미사용 잠금은 유지합니다.
- 일반 조회·기존 세션 확인·틀린 PIN·시도 제한·다른 교사 선택은 기기를 연장하지 않습니다. 만료·해제된 기기는 새 등록 링크가 필요하고 기존 PIN을 유지합니다.
- 계정별 PIN 5회 실패 시 15분 제한, PIN 변경 시 기존 세션 폐기, 로그아웃·현재 기기 해제를 지원합니다.
- 인증 거부는 직렬 실행 콜백 내부에서 HTTP 응답으로 변환합니다. PIN 불일치(401)·초대 만료(403)·시도 제한(429)이 저장소 재시작과 일반 처리 오류로 바뀌지 않으며 실패 횟수 기록을 보존합니다. 실제 workerd 기반 HTTP 등록→쿠키→세션과 오류 후 재시도를 검증합니다.
- 초대는 30분 동안 한 번만 사용합니다. 이메일 인증과 PIN 분실 자동 복구는 이번 범위에 포함하지 않습니다.
- 등록된 기기의 설정에서 현재 PIN을 재확인하여 자기 계정의 추가 기기 링크를 직접 발급합니다. POST /api/auth/device-invite는 유효 기기·세션·같은 출처 JSON과 현재 PIN을 요구하고 실제 노션 교사·담당반을 검증합니다. 클라이언트가 요청한 다른 교사·학급을 대상에 사용하지 않습니다.
- 직접 발급 링크는 발급 기기와 PIN 버전에 연결합니다. 동일 기기에서 재발급하면 이전 미사용 링크를 무효화하고 발급 기기 해제·만료·PIN 변경 뒤에는 미사용 링크로 등록할 수 없습니다. 새 기기는 링크와 기존 PIN으로 등록하며 기존 기기는 계속 사용할 수 있습니다.
- 발급 화면의 PIN·링크는 기기 저장소에 영구 보관하지 않습니다. 잠금·교사 전환·설정 닫기 시 입력과 링크를 지우고 진행 요청을 취소합니다. 30분 만료 시 복사할 링크를 숨깁니다. 응답은 no-store이고 등록 토큰은 링크의 fragment에만 둡니다.
- 등록 정보는 PIN 등록 성공까지 URL의 fragment에 유지하여 주소 복사·새로고침을 지원합니다. 만료된 링크도 등록된 기기의 정상 로그인 초기화를 막지 않습니다. 기존 계정은 새 기기에서도 기존 PIN을 사용합니다.
- 로그인에는 앱 버전과 로딩·실패 상태를 표시하고 연결 재확인을 제공합니다. PIN 로딩 중 키패드를 잠시 비활성화하며 통신 제한 후 다시 사용할 수 있습니다.
- 권한은 서버 세션과 실제 노션 담당반으로 검증합니다. 클라이언트가 보낸 교사·학급·원아 정보로 권한을 부여하지 않습니다.
- NOTION_PROXY 서비스 바인딩으로 minmin-notion을 호출합니다. 동일 계정 Worker의 공개 주소 호출 제한에 의존하지 않습니다.
- 공용 프록시의 보육 3대 DB와 하위 페이지·블록에는 서버 전용 인증을 적용하며 공개 전체 검색을 차단합니다. 그 외 공부방 경로는 유지합니다.
- Gemini 키는 서버 Secret에서 사용합니다. 호출 지역 오류 대응을 위해 서울 인근 배치 힌트를 설정했습니다. 국가 고정 보장을 의미하지 않습니다.

## 서식과 노션 저장 계약

### 누적 기억과 월·분기 서류

- 장기 기억의 원천은 노션의 관찰 원문·정확한 원아 관계·관찰일과 검수 저장본입니다. 브라우저 초안이나 AI 대화 기억에 의존하지 않습니다. 기기·세션의 30일 수명은 관찰 기록 보존 기간이 아니며 정상 관찰 기록을 기간 만료로 자동 삭제하지 않습니다.
- 이번 달/지난달/이번 분기/지난 분기는 작성일 기준으로 조회 기간을 채웁니다. 분기는 1~3·4~6·7~9·10~12월이며 진행 중 기간은 작성일까지입니다. 학기 등 다른 기간은 날짜를 직접 지정합니다. 기간 변경은 기존 선택과 진행 중 조회 결과를 폐기하고 재조회·재선택을 받습니다.
- 생성 요청의 evidenceFrom/evidenceTo를 서버가 검증하고 해당 기간의 실제 선택 ID만 읽습니다. 종료일 생략은 기존 요청과 호환되도록 작성일을 사용합니다. 실제 출처에 시작/종료일을 보존합니다.
- 오늘 자료 없이 작성하려면 원아·실제 과거 기록과 observation/hangroo_eval/counseling만 선택합니다. 일일 서류는 실제 당일 메모/사진을 요구합니다. 기간 전체를 자동 반영하지 않으며 조회 500건·생성 선택 60건 제한을 유지합니다.
- 월간은 참조 종료 월을 기본 대상으로 사용합니다. 교사의 지정 월·관찰일을 실제 선택 기록 또는 실제 당일 자료와 대조하고 AI가 다른 관찰일을 반환하면 거부합니다. 놀이/일상생활은 실제 내용 기준이며 없는 유형은 빈 날짜와 기록 부족으로 남깁니다. 평가·상담의 과거 근거는 날짜순으로 전달합니다.
- 과거 기록만으로 작성한 서류는 citation.historyOnly와 출처 요약의 [기간종합]으로 구분합니다. 원래 관찰을 덮어쓰거나 다른 기간 서류와 합치지 않습니다. 조회·복원은 지원하지만 새 관찰 근거로 선택·생성하지 못하게 하여 종합문을 새로운 사건으로 재사용하는 것을 막습니다. 기존 미표시 서류를 추측하여 소급 변경하지 않습니다.
- 복원은 검수 문장·선택 출처 ID·시작/종료일을 함께 복원합니다. 월간 전문 복사는 실제 화면을 복사하며 요약 복사에도 관찰일을 보존합니다. 발달평가 복사·HWP 표에는 실제 참조 기간을 표시합니다.

- 반 전체 메모는 입력 중 400ms 뒤 이름별 문장을 원문 그대로 제안합니다. 담당반 노션 실명과 3~4글자 한글 이름에서 성을 뺀 약칭을 문장/줄바꿈 경계와 조사로 찾습니다. 다른 일반 단어의 부분 일치를 피하며 임의 애칭·오탈자·붙여 쓴 문장까지 자동 판별하지 않습니다. 약칭·공동 문장은 확인 표시를 붙이고 동명이인은 원아 선택을 비웁니다.
- 같은 문장에 여러 아이가 등장하면 아이별 후보에서 행동 역할을 확인합니다. 이름 없는 이어지는 문장·반 공통 활동은 별도 목록에 보존하고 직접 원아를 선택해 후보로 추가할 수 있습니다. 앞 문장이나 모든 원아에게 자동 귀속시키지 않습니다. 반복 문장은 중복 제안하지 않으며 한 번에 후보 100건까지 표시합니다.
- 쉼표 뒤 새 이름이 주어/독립 키워드로 시작하면 원문 범위를 나눕니다. 상대에게 이어지는 문장은 공동 후보로 유지합니다. 문장부호 없는 긴 음성 전사 등은 여러 행동이 한 후보에 남을 수 있으므로 원문 범위를 줄이거나 줄바꿈을 넣어 확인합니다.
- 후보마다 원아·발췌·선택 요약을 수정하고 확인한 카드만 한 번에 저장합니다. 개인 원시 메모에 원문 발췌를 저장하며 원문 변경·카드 수정·복원 때 확인을 해제합니다. 수정 후보/저장 상태는 기존 AES-GCM 초안에 보관합니다. 저장 중 수정본을 보존하고 일부 성공 뒤 미저장 확인 항목만 재시도합니다. 이름 탐색 자체는 브라우저 안에서 실행하며 AI를 호출하지 않습니다.

- 7종: 키즈노트 알림장, 한그루 보육일지, 월간 관찰일지, 발달평가, 일일 보육일지, 학부모 상담 준비 초안, 놀이 지원안.
- 관찰·평가·상담은 원아 선택이 필요합니다. 개인 근거에는 정확히 한 원아의 실제 관계만 사용합니다. 여러 관계·조회되지 않는 원아·과거 반 전체 메모 자동 분할 기록은 연결 확인 필요로 표시하고 선택을 막으며 생성 API도 거부합니다.
- POST /api/logs/link-child {date,childId,sourceId,sourceRawMemo,excerpt,summary?,confirmed:true}. 실제 원아·교사·반·날짜, 노션 원문 일치와 발췌문의 부분 문자열 일치를 확인합니다. 원아가 지정된 원문은 같은 원아에게만 연결합니다. 교사의 사실 판단을 자동으로 대신하지 않습니다.
- 개인 행은 [원아연결:안정 식별자]로 구분하며 원시 메모에는 해당 발췌만 저장합니다. 전체 검수 JSON의 child_link에 원문 ID·URL·날짜·원문 해시·발췌·원아 ID·확인 교사·시각을 기록합니다. DB 속성을 추가하지 않습니다. 원문을 나중에 수정해도 이미 확인한 발췌를 자동 변경하지 않습니다.
- 기존 MemoStore의 교사·반·날짜·원아별 큐로 연결 쓰기를 직렬화합니다. 같은 원문·원아·발췌의 재시도는 같은 행을 조회하며 변경된 검수 요약은 같은 행에 저장합니다. 확인되지 않은 쓰기는 pending으로 보존해 새 생성을 중단하고 실제 반영을 확인합니다.
- AI의 가명은 서버의 노션 ID에 대응시키며 클라이언트가 받은 이름으로 첫 일치 원아를 고르지 않습니다. 반 전체 동명이인·알 수 없는 가명은 미확인으로 처리합니다. 카드의 후보 ID와 정확한 원문 발췌도 교사의 확인 후 저장합니다. 사진만 있는 관찰은 원문 메모를 먼저 보완해야 연결할 수 있습니다.
- 작성일자·학급·원아·작성교사·활동 구분·표준보육 영역·원시 메모·관찰 요약·알림장·관찰 최종본·참조 출처 요약을 실제 스키마에 저장합니다.
- 전체 검수 JSON은 페이지 본문의 ‘보육비서 검수 저장본 v1’ 제목 아래 JSON 블록으로 저장합니다. 업데이트 시 이전 본문을 보존하고 최신 저장본을 추가합니다.
- 같은 날짜·원아는 이어서 추가·덮어쓰기·별도 저장 중 선택합니다. 이어서 추가는 이전 메모와 검수본을 합칩니다.
- 저장 성공은 실제 노션 쓰기 성공 후 표시합니다. 연결 실패를 샘플이나 가짜 성공으로 바꾸지 않습니다.
- 검수 누락·중복 선택·전송·실패·성공을 지속 표시합니다. 저장 중 연속 탭을 제한하며 저장 도중 추가된 수정은 초안에 보존합니다. 문장을 수정하면 검수 확인을 다시 받아야 합니다.
- 잠금·교사 전환은 중복 선택과 진행 중 통신을 취소하고 저장 버튼 상태를 해제합니다. 늦게 도착한 이전 교사 응답은 새 학급 화면에 반영하지 않습니다. 읽기·인증 요청은 60초, 쓰기는 120초로 브라우저 대기를 제한하며 시간 초과와 연결 오류는 저장 완료로 처리하지 않습니다.
- 클라이언트 취소는 서버의 이미 진행된 노션 쓰기를 되돌리지 않습니다. 응답을 못 받거나 쓰기 도중 잠겼다면 보관함에서 해당 기록을 확인한 뒤 재시도합니다. 자동 쓰기 재전송은 하지 않습니다.
- 노션 429/529는 제한된 횟수 안에서 Retry-After를 따릅니다. 오래 기다려야 하는 경우 재시도를 안내하며, 응답 불명확한 쓰기는 중복 재전송하지 않습니다.
- 보관함은 50건씩 이전 기록을 불러옵니다. 근거 조회는 최대 500건, 생성당 선택은 최대 60건이며 기간을 좁혀 오래된 기록을 조회할 수 있습니다.
- 생성본은 원아·날짜·교사 문맥을 포함합니다. 대상 변경 시 이전 결과를 숨기며 문맥이 다른 저장은 서버가 거부합니다.
- AI 요청은 전체 110초의 제한 안에서 일시 장애와 서식 누락에 재시도·대체 모델을 사용합니다. 실제 응답의 서식 내용을 검사하고 빈 서식을 완료로 처리하지 않습니다. 결제 402·사용량 429·권한·지역·일시 장애·시간 초과를 구분하여 안내합니다.
- 관리자 POST /api/admin/verify의 notionOnly=true는 AI와 독립적으로 연구반 가상 기록의 쓰기·읽기·검수 문장 일치를 확인하고 즉시 보관 처리합니다.

## 임시보관과 사진

### 원시 메모 자동 저장·기기 공유

- GET /api/memo?date=YYYY-MM-DD&childId=… 및 PUT /api/memo {date,childId,rawMemo,baseVersion}. 서버 세션의 실제 교사·담당반과 노션 원아를 사용합니다. GET/PUT 응답은 no-store입니다.
- 입력 5초 대기·연속 입력 최대 30초마다 전송 시도, 화면 숨김/pagehide는 keepalive 추가 시도입니다. 동일 내용은 쓰기를 생략하고 빈 내용으로 노션을 삭제하지 않습니다. 종료 시 전송과 암호화 전 강제 종료의 복구는 보장하지 않습니다.
- 최초 진입·대상 변경·화면 복귀·활성 화면 30초마다 노션을 조회합니다. 편집·검수 중 다른 버전은 충돌로 표시하고 교사가 두 메모 합치기/노션 메모 사용을 선택합니다. 원아·날짜·잠금 후 늦은 응답은 화면에 반영하지 않습니다.
- MemoStore Durable Object는 교사·학급·날짜·원아별 쓰기를 직렬화합니다. 본문·변경 ID·노션 수정 시각의 해시로 버전을 비교하며 오래된 쓰기는 현재 메모를 포함한 409로 거부합니다. 노션 직접 편집도 버전 변경으로 감지합니다.
- 일지 DB의 [원시메모:안정 식별자] 행에 원시 메모·작성교사·학급·원아·작성일자와 참조 출처 요약의 자동 저장 메타데이터를 함께 저장합니다. 반복 수정은 같은 페이지의 속성만 갱신하며 블록과 검수 최종본을 변경하지 않습니다. 이 행은 memoOnly로 보관함·근거 선택에 표시하고 완성 일지의 중복 선택 대상에서 제외합니다.
- 불명확한 쓰기는 Durable Object의 pending으로 기록하고 노션 변경 ID의 반영을 조회합니다. 확인 전 재생성·새 내용 쓰기를 하지 않습니다. 명확한 노션 400/401/403/429 거부는 연결 복구 후 재시도를 허용합니다. 장기간 미반영 pending은 관리자 확인이 필요합니다.
- 미전송 메모·예상 버전·기준 원문을 대상별 AES-GCM 기기 보관합니다. 키는 인증 후 메모리에만 둡니다. 메모만 있는 기존 초안은 노션 공유본과 비교하고 사진·검수본이 있는 초안은 기존 이어쓰기 확인을 유지합니다.
- 사진 자동 업로드·과거 메모 소급 이관·빈 메모 삭제·반 전체 자동 원아 분할은 이번 범위에 포함하지 않습니다. 원시 메모 저장과 검수 완성본 저장은 각각 표시합니다.

- 메모·검수본·날짜·원아·근거·사진을 교사별 AES-GCM으로 기기 임시보관합니다. 복호화 키는 인증 후 서버에서 받아 메모리에만 둡니다.
- 빈 초기 화면이 이전 초안을 덮지 않습니다. 재진입 시 이어서 작성 또는 지우기를 먼저 선택합니다.
- 브라우저 데이터 삭제·저장 공간 부족·비동기 저장 이전 강제 종료까지 100% 복구한다고 보장하지 않습니다. 사진 때문에 용량을 넘으면 문서부터 보관하고 재첨부를 안내합니다.
- 사진 최대 6장을 긴 변 1280px JPEG로 재인코딩하여 용량을 줄이고 원본 위치 메타데이터를 전달하지 않습니다. 얼굴·이름표는 교사가 직접 가리며 외부 AI 전송 동의를 확인합니다.

## 사실과 개인정보의 한계

- 등록된 해당 반 원아의 실명·고유한 이름 약칭·교사명은 서버에서 가명화하여 AI에 보내고 결과를 복원합니다. 미등록 이름과 사진 속 신원까지 자동 제거한다고 보장하지 않습니다.
- 과거 기록을 오늘 사건으로 바꾸거나 없는 식사·발화·지원·상담 합의를 만들지 않도록 지시하며 부족한 영역을 표시합니다. AI 오류를 완전히 없애는 보장은 없습니다.
- 미기록/미확인을 행동 부재로 바꾸지 않도록 지시합니다. 실제 AI 가상 사례에서 표현 차이가 발견되어 지침을 강화했으며 자동 문장별 사실 판정이 완성된 것은 아닙니다.
- 출처는 실제 선택한 노션 ID·날짜·URL로 서버에서 구성합니다. 문장별 자동 사실 판정·인용까지 완성된 것은 아니므로 교사가 확인해야 합니다.
- 기존 공개 배포 Gemini 키는 보육비서 전용 키로 분리해야 합니다. 다른 앱의 키 배포 기능 종료·키 교체는 별도 작업입니다.
- 기존에 누락되거나 잘못 연결된 기록을 추측하여 소급 생성하지 않습니다. 교사가 실제 자료로 확인·보완해야 합니다.
- 전체 JSON이 없는 이전 형식은 상세 보기·복사·원문 인쇄와 원시 메모 복원을 지원하며, 사라진 전체 서식을 다시 만들었다고 표시하지 않습니다.
