# 보육비서 인증과 장기 기록 복원 실행 계획

## 목표

교사는 등록된 휴대폰에서 4자리 PIN으로 담당 반에 들어온다. 검수한 기록을 노션에 저장하고, 이후 관찰일지·발달평가·상담일지를 작성할 때 해당 원아의 실제 관찰 요약과 원시 메모를 근거로 활용한다.

## 작업 순서

1. 현재 노션 교사·원아·일지 DB 구조와 배포 환경을 확인하고, 별도 작업 브랜치에서 진행한다.
2. Worker에서 기기 등록, PIN 확인, 시도 제한, 세션 발급·만료·취소, PIN 변경을 처리한다. 자격 증명은 서버 전용 저장소에 두고 교사 프로필과 보육 기록은 노션을 원천으로 사용한다.
3. 모든 원아·일지 조회·변경 요청에서 서버가 교사의 담당 반과 대상 기록의 소유권을 확인한다. 연구반에는 가상 자료만 제공한다. AI 키 전달 경로를 닫는다.
4. 생성 전 같은 원아의 과거 기록을 기간별로 조회하여 관찰 요약과 원시 메모를 함께 제공한다. 기록이 없거나 근거가 부족하면 성장 변화를 만들어내지 않는다. 선택한 근거와 날짜를 결과에 표시한다.
5. 노션 저장에 작성 교사와 원아 관계, 검수한 전체 결과, 원시 메모, 관찰 요약을 함께 보존한다. 학급 메모의 개별 관찰은 검수한 원아별로 축적한다. 실제 저장 실패와 모의 저장을 구분한다.
6. 이력 조회·중복 확인·복원과 교사별 임시보관을 연결하고, 실제 한그루 필드 복사 흐름을 확인한다.
7. 인증 우회·타 학급 접근·세션 만료·PIN 변경·기록 저장/조회/재생성에 대한 동작 검증과 모바일/PC 화면 확인을 수행한다. 결과를 walkthrough.md에 기록한다.
8. 명세서·사용가이드·부품 도감을 갱신하고 GitHub에 반영한다. 검증 후 Worker를 배포하고 scripts/log_dev_timeline.py로 노션 개발/일상 기록을 남긴다.

## 운영 전 준비

- Cloudflare 배포 인증이 필요하면 사용자가 본인 계정에서 로그인한다.
- 두 교사의 최초 기기 등록에는 단기 일회용 초대 링크를 사용한다. 초대 토큰·PIN·세션·API 키는 소스나 Git에 저장하지 않는다.
- 이메일 로그인을 선택할 경우 실제 교사 이메일과 Cloudflare Access 정책을 확인한다. 이메일 주소 입력만으로 로그인시키지 않는다.
- 실제 원아 기록을 사용하는 검증은 내용을 외부 로그에 출력하지 않는다. 쓰기 검증에는 연구용 기록을 사용하고 결과를 구분한다.

## 완료 기준

- 인증 없이 실제 원아/기록과 AI 키에 접근할 수 없다.
- 사랑반과 소망반 자료가 서버에서 분리된다.
- 저장 성공 표시에는 실제 노션 페이지가 존재한다.
- 과거 기록의 관찰 요약과 원시 메모가 다음 생성 요청까지 전달되고 사용한 근거를 확인할 수 있다.
- 다시 열거나 인증이 만료돼도 본인 작성 중 메모와 검수 결과를 복원할 수 있다.
- 모바일 화면, 노션 저장/조회, 한그루 복사와 배포 결과를 직접 확인한 범위만 완료로 보고한다.
