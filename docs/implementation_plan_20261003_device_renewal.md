# PIN 인증 시 기기 등록 자동 연장 계획

## 승인한 동작

등록된 휴대폰에서 기존 PIN 인증에 성공하면 서버의 기기 만료 시각과 HttpOnly 기기 쿠키를 그 시점부터 30일 연장합니다. 만료·해제된 기기, 잘못된 PIN, 시도 제한, 다른 교사 선택은 연장하지 않습니다. 기존 PIN·학급 권한·1시간 미사용 잠금은 유지합니다.

## 구현 순서

1. api/auth.js의 login에서 PIN 검증과 세션 저장 성공 후 기기 만료 시각을 저장하고, 기존 기기 토큰과 30일 쿠키 수명을 반환합니다. 기존 Worker의 쿠키 발급 경로를 재사용합니다.
2. 조회·세션 갱신은 기기 기간을 연장하지 않으며 기존 기기의 다음 성공한 PIN 인증부터 적용합니다.
3. 실제 workerd에서 기기 저장 만료 시각을 조정해 연장 전후를 검증합니다. 성공 응답의 기기·세션 쿠키, 쿠키 수명, 원래 만료일 이후 로그인, 틀린 PIN·다른 교사·만료·해제·5회 제한의 미연장을 확인합니다.
4. 화면의 ‘30일 기억하기’ 문구를 실제 세션·기기 정책과 맞추고 명세·부품 지도·가이드·검증 보고서를 갱신합니다.
5. 가상 자료의 모바일·PC PIN 화면과 쿠키/세션 연결, 전체 회귀, Node 문법·파일 크기, 전사 AI 공개 HTML 검증 후 운영 배포·Git 푸시·노션 기록을 수행합니다.

## 완료 기준

- 성공한 PIN 인증은 서버 기기 만료와 브라우저 기기 쿠키를 같은 30일로 갱신합니다.
- 여러 기기를 등록한 같은 교사도 각 기기의 연장·해제가 독립적으로 적용되고 기존 기기 등록을 유지합니다.
- 기기 등록을 해제하거나 30일 동안 PIN 인증하지 않은 기기는 새 링크를 요구합니다.
- 인증 없는 조회·틀린 PIN·시도 제한·다른 교사 선택은 연장하거나 접근을 부여하지 않습니다.
- 운영 사용자 PIN을 대신 입력하거나 바꾸지 않습니다. 자동 연장은 배포 이후 다음 PIN 인증부터 적용됩니다.
