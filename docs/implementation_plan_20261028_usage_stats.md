# 선생님 사용 현황 조회 · 2026-10-28

- A: 관리자가 기간별로 교사마다 접속 횟수·사용한 날·대략의 사용 시간·접속 시각(KST)·서식 생성·완성 저장 횟수를 조회한다.
- S: api/auth.js(AuthStore SQLite 표 usage_visits 1개·기록·조회·90일 정리), worker.js(생성·저장 성공 기록, POST /api/admin/usage), 인증 실행기 시험과 문서만 수정한다. 노션 DB·wrangler.toml·공용 프록시는 바꾸지 않는다.
- D: AuthStore는 단일 Durable Object에 키-값으로 계정·기기·세션을 저장하고 보호 API마다 session을 확인한다. 화면은 30초 메모 동기화·5분 보안 확인으로 세션을 부르므로 호출 수를 그대로 세면 접속이 부풀려진다.
- S: 접속 1회 1행에 교사 ID·시작 종류(register/login/resume)·시작/마지막 활동 시각·기기 표시값(기기 해시 앞 12자리)·생성/저장 횟수만 둔다. IP·브라우저 정보·메모·원아 정보는 남기지 않는다. 30분 넘게 활동이 없으면 새 접속(재개)으로 센다. 마지막 활동은 5분마다 갱신한다. 기록 실패는 로그인·생성·저장을 막지 않는다. 조회는 AUTH_ADMIN_SECRET·같은 출처 JSON POST·no-store, 기간 최대 92일. 시작 후 90일이 지난 접속은 매일 알람이 지운다. 배포 전 사용은 소급하지 않는다.
- T: 실제 workerd 가상 계정으로 로그인 1건, 30분 안 세션 확인 미증가, 30분 공백 후 재개, 생성·저장 성공만 증가, 무효 세션·잘못된 종류 거부, 관리자 비밀값·출처·POST 요구, 응답 항목 제한, 89일 유지·91일 삭제를 확인한다. npm test와 계약 검사 통과.

선생님께는 사용 가이드에 수집 항목·보관 기간·조회자를 미리 안내한다. 노션 일·주 요약은 이번 범위에서 제외한다.
