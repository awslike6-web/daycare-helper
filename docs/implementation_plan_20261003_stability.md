# 보육비서 현장 오류 복구 계획

## 대상과 목표

사랑반 사진 생성 지연·일부 서식 누락·노션 저장 실패, 연구반 등록 실패, 모바일 화면 문제를 실제 호출 경로에서 확인한다. 기존 원아 기록은 수정하지 않고 가상 연구 자료로 재현한다.

## 순서

1. 운영 로그의 경로·상태·안전한 오류 분류와 배포 CSS/JS 버전을 확인한다. 사용자 오류 화면은 개인정보를 제외하고 확인한다.
2. AI 생성과 독립된 관리자 노션 검증을 마련하여 연구반 가상 기록의 저장·조회·검수본 일치를 확인하고 보관 처리한다.
3. 등록 링크 만료·사용 여부·PIN 등록 상태를 구분하고, 새로고침과 모바일 링크 전달에 필요한 등록 문맥을 보존한다. 인증·학급 격리는 유지한다.
4. 요청한 서식이 실제 응답에 있는지 확인한다. 생성 지연·일시 장애·결제·권한 오류를 구분하여 안내하고 메모·검수본을 보존한다.
5. 실제 저장 요청과 검수·중복 확인 단계에 진행·실패·성공 상태를 표시한다. 빈 저장 성공을 표시하지 않는다.
6. 모바일·PC 화면과 가상 자료의 등록/생성/검수/저장/조회 흐름을 재검증한다. 사용자 화면을 받지 못한 부분은 확인 한계로 남긴다.
7. 명세·부품 지도·사용법·검증 보고서를 갱신하고 운영 배포·한국어 Git 커밋/푸시·노션 장애 분석 기록을 수행한다.

## 완료 기준

- AI 장애 상태와 실제 노션 저장 실패를 구분할 수 있다.
- 노션 가상 쓰기·읽기 검증이 AI 연결 상태와 무관하게 수행된다.
- 등록 중 새로고침 또는 만료된 링크가 정상 등록된 기기의 접속을 막지 않는다.
- 누락된 서식을 전체 완료로 표시하지 않는다.
- 화면과 저장본은 교사가 검수한 문장으로 일치한다.
- 실제 교사 PIN을 대신 설정하거나 기존 실제 기록을 덮어쓰지 않는다.
